# 语音转文字模型选型与评测

2026-10-03。这份文档回答三件事：本地语音转文字（STT）该预置哪些模型、凭什么选它们、选完还有哪些没验证。后端与协议背景见 [speech-to-text-backends.md](speech-to-text-backends.md)（旧调研，其 §3 候选与 §7 首期推荐已被本文的实测取代），worker 与主程序的接入细节见 [../guides/snow-stt-worker.md](../guides/snow-stt-worker.md)。

标记约定沿用旧调研：【实测】本机跑出的数据；【已核实】读到一手来源（本仓库代码、清单、评测原始输出）；【二手】非一手来源；【未验证】没有证据，不能当事实。

## 0. 结论摘要

| 维度 | 语言 | 默认（性价比） | 备选 |
|---|---|---|---|
| 流式 | 纯中文 | multi-zh-hans-2023-12-12（163MiB，CER 5.71%） | zh-int8-2025-06-30（262MiB，CER 4.98%，最准） |
| 流式 | 纯英文 | en-2023-06-26（161MiB，WER 3.11%） | en-2023-06-21（255MiB，WER 2.50%，最准） |
| 流式 | 中英双语 | x-asr 480ms（269MiB，合并 5.56%）——用户已定 | x-asr 160ms（延迟更低，合并 6.62%，CPU 更重） |
| 离线整句 | 纯中文 | paraformer-zh-small（186MiB*，CER 5.08%） | paraformer-trilingual（369MiB*，CER 4.07%，并列最准里内存最小） |
| 离线整句 | 纯英文 | zipformer-small-en（358MiB*，WER 2.11%） | zipformer-en-2023-06-26（408MiB*，WER 1.77%，最准） |
| 离线整句 | 中英双语 | x-asr 离线（667MiB*，合并 3.81%）——用户已定 | SenseVoice 2024（415MiB*，合并 5.70%；关 ITN 为 4.08%）——用户已定 |

\* 离线峰值是 Python 进程口径，不等同于 Rust worker，见 §2.3。流式与离线是两个独立维度，**不要跨维度比较排名**，也不要把两张表的绝对数字拿来对照（口径差异见 §2.3、§2.4）。

语音翻译：端到端不可行，采用「STT 定稿 → 现有 `snow-translate`」的级联，见 §6。

## 1. 目的与范围

- 流式（`OnlineRecognizer`，边说边出字）与离线整句（`OfflineRecognizer` + VAD 切句，说完一句再出）延迟特性、使用场景、模型家族都不同，各自选型，互不排名。
- 每个维度再分纯中文、纯英文、中英双语三组，每组选一个「默认值（性价比）」和一个「备选（准确率最高，或有明确特点）」。
- 只评本地模型。Windows 系统语音后端不在评测内（它不能喂 PCM，没法同口径对比，见 worker 文档）。
- 只评准确率、内存、加载、速度、许可证。真机麦克风的实际听感与延迟没评，见 §8。

## 2. 评测方法

### 2.1 机器与软件
Ryzen 9 7945HX、Windows 11；推理 2 线程、进程优先级 BelowNormal；onnxruntime 1.28.2、sherpa-onnx 1.13.8【实测】。语音翻译评测另用 ORT 1.28.0（见 §6）。不同机器、GPU 的数据不能直接对比。

### 2.2 测试集
固定随机种子 20261003，抽样后转 16k 单声道 wav：
- 中文：AISHELL-1 test 抽样 200 句（2853 字）。
- 英文：LibriSpeech test-clean 抽样 200 句（4121 词）。
- 中英混说：把中文句与英文句**拼接**成的合成集，100 条（3557 个计分单位）。注意它只是**句间切换**，不是真实的句内混说（比如「帮我 review 一下这个 PR」那种），所以它偏乐观地反映了双语模型的切换能力，对句内混说没有代表性。
- 双语模型的「合并」成绩 = 三个集合的错误数相加 / 计分单位相加（共 10531 个）。

### 2.3 计分规则与口径差异
- 中文按字、英文按词、混说按「中文字 + 英文词」混合计。
- 英文统一转大写、去标点、保留撇号；中文去标点；`▁` 与 `<unk>` 当空白。
- 错误率 = 编辑距离 / 参考长度。95% 区间是按句 bootstrap。
- 流式的准确率用 sherpa-onnx Python 批量识别算出；性能项（峰值内存、加载、RTF）用 Rust worker `snow-stt` 走真实协议跑。两者输出一致性另做了核对（§2.5）。

**口径差异，读表前务必看清：**
1. **峰值内存**。流式表里的峰值是 Rust worker（`snow-stt`）进程的 `PeakWorkingSet64`，单位 MiB。离线表里是 **Python 进程**的峰值（Python 基线，即只 `import sherpa_onnx` 不加载模型，是 35.8MiB），表里给「原始」与「扣基线」两列。Python 口径不等同于 Rust worker，实际内存会略有出入，**离线峰值只能当相对大小看**。选型规则里用的是「原始」值。
2. **繁转简**。离线评测在计分前做了繁转简，流式评测没做。所以流式与离线的绝对数字不可跨维度对照（Whisper-base 的中文输出里有 158 句含繁体，是这条规则影响最大的模型）。
3. **流式性能项**：用把各集合拼起来的长音频（中 67.13 秒、英 71.67 秒、混 79.58 秒），3 轮、取中位数、模型之间交替运行。
4. **离线评测没有 VAD 环节**，整句 wav 直接喂识别器。所以 VAD 参数的影响没有评过（§7 第 4 条）。

### 2.4 离线评测的其它说明
- 每个模型独立新进程，3 轮交替；RTF 取中位数。
- 三轮输出逐字一致（表中 `consist=True`），说明解码是确定性的。
- SenseVoice 的逆文本规整（ITN）会把中文数字转成阿拉伯数字，评测里被计为错误。关 ITN 的对照只跑了 1 轮：合并错误率 **4.08%**，开 ITN 为 **5.70%**。产品默认开 ITN（带标点与数字格式更适合键入），这个差距是评测口径造成的，不是识别变差。

### 2.5 snow-stt 与 Python 输出一致性【实测】
每个流式模型每个集合抽 20 句，比较 `snow-stt` 与 Python 的文本：除 x-asr 160ms 外全部 20/20 一致。x-asr 160ms 在中文集与混说集各有 1 句不同（同一句，「百生办」对「北山办」，单字差异）。结论：Rust worker 与 Python 的识别结果可视为一致，评测用 Python 算准确率不影响对 worker 的结论。离线模式没有做 snow-stt 对 Python 的逐句对照，只做过 wav 上的跑通检查【未验证】。

## 3. 选型规则

1. 每组先留下「错误率不超过该组最优值 1.25 倍」的候选；
2. 在这些候选里取**峰值内存最小**者作默认；
3. 同时给 1.20 倍的敏感性说明，看结论稳不稳。

备选取「准确率最高」者（并列时取内存更小者），双语流式因为默认本身就是最准的，备选改取低延迟变体。用户已拍板的项（流式双语默认 x-asr 480ms；离线双语默认 x-asr 离线、备选 SenseVoice 2024）优先于规则。

规则应用结果：

| 维度 / 组 | 最优错误率 | 1.25 倍线入围（内存升序） | 1.25 倍的默认 | 1.20 倍的默认 |
|---|---|---|---|---|
| 流式 zh | 4.98%（2025-06-30） | multi-zh-hans 5.71%（163）、2025-06-30（262） | multi-zh-hans | 同（5.71% 在 5.98% 线内） |
| 流式 en | 2.50%（06-21） | 06-26 3.11%（161）、02-21 2.79%（202）、06-21（255） | 06-26 | **02-21**（202MiB）：06-26 的 3.11% 略高于 3.00% 线 |
| 流式 bilingual | 5.56%（x-asr 480ms） | x-asr 160ms 6.62%（268）、x-asr 480ms（269） | 规则上 160ms 仅小 1MiB，属并列；用户定 480ms | 同 |
| 离线 zh | 4.07%（xasr、paraformer-trilingual） | paraformer-zh-small 5.08%（186）、zipformer-ctc-small-zh 4.17%（342）、paraformer-trilingual（369）、zipformer-zh-en-2023-11-22（539）、xasr（667） | paraformer-zh-small（5.08% 刚好在 5.09% 线内） | **zipformer-ctc-small-zh**（342MiB） |
| 离线 en | 1.77%（zipformer-en-2023-06-26） | zipformer-small-en 2.11%（358）、06-26（408）、zipformer-zh-en-2023-11-22 1.94%（539） | zipformer-small-en | 同 |
| 离线 bilingual | 3.81%（xasr） | 仅 xasr（667） | xasr | 同 |

几点说明：
- 流式 en 的 06-26 与 06-21、02-21 之间的差距：按句配对 bootstrap，06-21 比 06-26 差的比例仅 0.65%（06-21 明显更准），06-21 比 02-21 差的比例 10.2%，06-26 比 02-21 差的比例 91.1%。清单只收 06-26（默认）与 06-21（备选），02-21 不收。
- 流式 zh 里 2025-06-30 比 multi-zh-hans 差的比例是 5.85%，倾向 2025 更准但不到常用显著线。
- 离线 zh 默认 paraformer-zh-small 是**压线入围**（5.08 对 5.0875），1.20 倍就换成 zipformer-ctc-small-zh 了。清单里没有后者；要不要换，取决于更在意 62.7MB 的体积还是 342MiB 的峰值，目前按规则保持 paraformer-zh-small。
- 离线双语：若 SenseVoice 的 ITN 差异按「关 ITN」口径计（4.08%），它落在 1.25 倍线（4.76%）内、且内存（415MiB）小于 x-asr（667MiB），规则会选它做默认。默认选 x-asr 是用户已定：它综合最准、输出自带标点与大小写，代价是内存更大，设置页里有内存警示。

| 变体 | BLEU [95%] | chrF | RTF | 峰值 MiB |
|---|---|---|---|---|
| medium int8 | 13.42 [11.91, 14.85] | 43.71 | 1.017 | 2632 |
| medium q4 | 14.13 [12.62, 15.74] | 43.99 | 1.342 | 2347 |
| medium int8（sherpa 运行时） | 13.47 [12.22, 14.80] | 44.57 | 1.635 | 3027 |
| small int8 | 6.88 [5.76, 8.11] | 35.29 | 0.430 | 1216 |

- 质量：medium 的 BLEU，CoVoST2 约 10.4~12.0、FLEURS 约 13.4~14.1，与官方公布的 14.0 / 15.1 同量级【二手：官方数字未在本次材料里复核】。small 基本不可用（3.67 / 6.88）。
- 量化：以 fp16 为基准，int8 的 BLEU 差 -0.29（区间 [-2.17, 1.57]）、q4 差 -1.65（区间 [-4.20, 1.21]），BLEU 差值的区间都跨 0；q4 在 chrF 上略显著（-1.77，区间 [-3.35, -0.09]）。q4 与 int8 在 FLEURS 上的差距在区间内，统计上看不出差异。q4 与 int8 的直接配对差值表里没有列【未验证】。
- 代价：CPU 上 RTF 约 1~2，**不能实时**（RTF 大于 1 即解码比说话慢）。Python 进程峰值 2.3~2.6GB（int8/q4）。encoder 原图带 24 个 attention 输出，int8 峰值曾达 5.6GB（5657MiB），裁掉这些输出后约 2.5GB（2540MiB）。
- 方向：Whisper 只能译成英文。
- 没测完：fp16、q4f16、bnb4 在 FLEURS 上被中止，没有数据。延迟与内存是并行单轮量级的参考，不是严格交替多轮的中位数。

### 6.2 英译中没有合适的小模型
- Granite-4.0-1b-speech 官方支持 en→Mandarin，但 ONNX q4f16 约 1.49GB【二手】，不适合预置。
- Seamless：许可证 CC-BY-NC（非商用）且过大【二手】。
- Canary：没有中文【二手】。

### 6.3 结论
端到端语音翻译在 CPU 上既慢、又吃内存、又只能译英文，不采用。采用**级联**：STT 定稿一句，交给现有 `snow-translate`（本地 NLLB / OPUS-MT 等，已有评测与发布流程，见 [../guides/translation-model-release.md](../guides/translation-model-release.md)）。主程序里的实现见 worker 文档「语音翻译级联」一节。

## 7. 已知限制与注意

1. **wenetspeech-20230615** 的 onnx 放在压缩包的子目录里，`snow-stt` 按目录平铺查找，不能直接加载（兼容性检查里原目录报缺 `encoder*.onnx`，摊平副本 `-flat` 能加载），所以不纳入清单。
2. **SenseVoice 的 ITN**：默认开启，会把中文数字转阿拉伯数字，评测里被计为错（关 ITN 4.08%，开 ITN 5.70%）。
3. **x-asr 离线峰值 667MiB**（Python 口径）偏大，设置页对该模型有内存警示。
4. **离线 VAD 参数没有评测**：默认值是 threshold 0.5、静音 500ms、最短语音 250ms、最长 20000ms（取自 sherpa 示例常见值）。已知静音 500ms 会把较长的中文句子切成两段，真实麦克风下是否合适要复测。
5. **whisper-base** 在中文上大量幻觉与繁体输出，不进清单。
6. **zh-14M、en-20M** 错误率很高（13.46%、23.49%），不建议使用，也不进清单。
7. **许可证未核实**：评测的 14 个离线模型里，清单里标「unverified」的有 5 个（x-asr 流式 480ms/160ms、x-asr 离线、paraformer-zh-small、paraformer-trilingual），SenseVoice 2024 标 FunASR 模型许可，未逐条核对条款。评测过但不在清单里的模型许可证同样没核。此前记录过「7 个模型许可证未核实」，与清单现状（5 个 unverified、1 个 FunASR 条款）不完全一致，以清单为准，核对时一并复查。
8. **sha256 未固定**：清单里 7 个模型压缩包的 sha256 为空（GitHub 没有返回 digest）：流式 en-2023-06-26、en-2023-06-21、bilingual-2023-02-20，离线 paraformer-zh-small、paraformer-trilingual、zipformer-small-en、zipformer-en-2023-06-26。下载器对空 sha256 放行（只校验大小）并提示，**发布前必须固定**。
9. **中英混说评测集是合成的**，不能代表句内混说，见 §2.2。

## 9. 复现方法

评测脚本和产物都在本机 `D:\workspaces\Cisox\build\stt-eval*\`。`build\` 被 gitignore，**不入库**；测试音频、下载的模型包已清理，需要时按各目录的 `prep_data.py`（种子固定 20261003）重建，模型从 sherpa-onnx 的 `asr-models` 发布页重新下载（大文件用 aria2）。

| 目录 | 脚本 | 用途 |
|---|---|---|
| `stt-eval\`（流式主评测） | `prep_data.py` | 抽样并转 16k wav，生成 zh/en 集合与 manifest |
| | `models.py` | 模型清单与分组 |
| | `run_acc.py <模型目录> <zh\|en\|mix> [out.json]` | sherpa-onnx Python 批量识别算 CER/WER |
| | `run_stt.py` / `perf.py` | 走 `snow-stt` 真实协议跑拼接长音频，量峰值内存、加载、RTF（3 轮交替） |
| | `consist.py` | `snow-stt` 与 Python 逐句一致性（每组 20 句） |
| | `compat.py` | 各模型目录能否被 `snow-stt` 直接加载 |
| | `agg.py` | 汇总表、bootstrap 区间、配对差异、合并成绩，输出 `summary.txt` |
| | `extract.py`、`lic.py`、`acc_all.sh` | 解压模型包、查许可证元数据、批量跑准确率 |
| `stt-eval-xasr\` | `mk_mix.py`、`run_acc.py`、`perf.py`、`consist.py`、`agg.py` | x-asr 480ms/160ms 追加评测，复用同一批数据与口径，结果在 `results\summary.txt` |
| `stt-eval-offline\` | `models_off.py`、`off_run.py`、`run_all.py` | 离线模型清单、单模型单进程评测、编排（每模型新进程、BelowNormal、3 轮交替、基线空进程 3 次） |
| | `agg_off.py` | 计分（与流式同规则，加繁转简）、性能中位数、选型表，输出 `summary_offline_raw.txt` |
| | `smoke.py`、`lic_off.py` | 抽 5 句冒烟、查许可证元数据 |
| `stt-eval-s2tt\` | `prep_data.py`、`eval_arm.py <臂> <集合> <out.json>` | 抽样 CoVoST2 / FLEURS zh→en 各 300 句；单进程跑一个评测臂（m-int8、m-q4、m-fp16、m-q4f16、m-bnb4、s-int8、sherpa-m-int8） |
| | `trim_enc.py`、`run_timing.sh` | 去掉 encoder 的 attention 输出；串行交替的计时与内存轮次 |
| | `agg.py <集合> <目录>` | BLEU、chrF 与配对差值，输出 `results\*_table.txt` |

关键命令（在对应目录下，需要 Python、sherpa-onnx、sacrebleu 等本机环境）：
```
python run_acc.py <模型目录> zh results\acc_<模型名>_zh.json    # 流式准确率
python perf.py                                                  # 流式性能（需先构建 snow-stt）
python agg.py                                                   # 汇总
python run_all.py ; python agg_off.py                           # 离线评测与汇总
python agg.py covost results\A ; python agg.py fleurs results\A # 语音翻译汇总（在 stt-eval-s2tt）
```
`snow-stt` 的构建见 worker 文档（本机用 `build\stt-eval\build-snow-stt-lf.ps1`，即仓库脚本的 LF 副本，原因见该文档「构建」一节）。
